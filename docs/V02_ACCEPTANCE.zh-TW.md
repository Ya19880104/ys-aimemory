# 0.2 內網試用版驗收範圍

這份清單定義本次擴充的交付條件。勾選必須有實際測試證據，不能因程式碼存在就視為通過；最終結果統一記錄於測試報告。

## 人類管理網頁

- 帳號密碼登入，預設唯讀；只有部署者明確配置的 admin 能寫入
- 新增已授權範圍內專案、來源、任務；瀏覽、搜尋、來源匯入
- 提案核准與管理員恢復／重新指派有明確確認、版本門檻與稽核
- 所有寫入通過 CSRF、身分、專案範圍與服務端角色驗證
- 表單錯誤、重送、過期版本與部分匯入錯誤有可理解的結果
- 不顯示或接受模型供應商登入 cookie；不把網頁 session 當成 MCP 身分

## 記憶與索引

- PostgreSQL 全文索引與 SQLite FTS5 測試路徑；中文子字串回退須明確標示
- 來源內容保留原始空白與換行，hash 可重現
- 批次匯入有大小上限、revision 比較、冪等 key 與整批交易
- 重試相同內容不重複建立來源版本；相同 key 搭配不同資料被拒絕
- 來源變更和衍生索引一致；可查看索引健康與明確執行重建
- 搜尋只能讀目前身分有權限的專案；待審提案不能冒充核准決策
- 從 0.1 資料結構升級保留來源、任務、交接與稽核，不清空資料庫

## 四 AI 的完整交接

- 四個獨立身分可由 inbox 找到各自需要接手的任務
- 每次接手取得目前版本，讀必要來源後才能確認、接受與提交
- 同時認領、租約過期、舊 fence、舊來源版本、跨身分封包均驗證
- A → B → C → D 交接保存成果 commit、檔案、測試、阻礙與下一步
- 中途核准記憶會使舊 context 失效；必須重讀後再繼續
- 指定接手者離線時，由 admin 用版本門檻與原因恢復，舊持有者失去提交權
- 系統保存測試聲明與證據，不宣稱能證明 AI 理解或阻止本機繞過工作流程

## 環境與交付

- 在乾淨 Python 環境執行全部回歸與整合測試
- 嘗試真實 PostgreSQL 執行並明確記錄版本；另外驗證備份還原
- Docker／HTTPS／正式 Windows 客戶端／實際瀏覽器 QA 分別報告，未執行不得列為通過
- GitHub 建庫與推送僅在登入成功後驗證；不能以程式包取代「已推送」的事實
- 仍以專用內網試用為目標；公網啟用須另行完成安全與營運驗收
