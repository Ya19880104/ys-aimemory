# Worker credentials and generated client bundles

[English](MCP_GENERATOR.md) | [繁體中文](MCP_GENERATOR.zh-TW.md)

Enable web MCP administration with `HUB_WEB_MCP_ENABLED=true` and a stable `HUB_WEB_OWNER_ID`. Administrators create/select a project and issue separate scoped worker identities. Tokens are displayed once; store privately and never distribute administrator credentials to general AI workers. Generated configurations contain endpoint/project metadata and environment references, not token values.

HTTPS `/downloads/ys-memory-stdio-1.1.1.zip` is generated by your deployed Hub using its configured origin/public CA, not a universal preconfigured GitHub release. It includes bridge/configuration/public CA/requirements/instructions. Missing or invalid public CA disables bundle download. The origin is not inferred from an untrusted request Host.

Extract into a new directory, create Python 3.12 venv, install `requirements.lock`, and print configuration with `bridge.py --compact --print-claude-config`. Manually merge into the intended project or use [Windows setup](CLAUDE_WINDOWS_SETUP.md). Preserve other MCP servers and global settings.

Compact has two initial tools and only connects upstream on explicit calls. Connected proves local readiness, not native acceptance; `memory_call` can forward writes. CA rotation requires independent reverification/new bundle rather than silently changing a pin.

Rotation preserves identity/message history but rejects old credentials on subsequent requests. Revocation does not delete historical messages, cancel already authenticated in-flight operations, or transfer a task. Disabling the management feature does not revoke existing tokens. Use guarded task recovery when needed. Additive credential/message schemas require backups and version-matched rollback, not old binaries against new DBs. See [client setup](CLIENT_SETUP.md) and [deployment](DEPLOYMENT.md).
